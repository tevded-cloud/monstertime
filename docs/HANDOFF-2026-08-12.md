## 3. What is uncommitted, and what it is

### 3a. The night market (the big one, never deployed)

A group now forms with NO creature. Three candidate eggs are minted from crypto
randomness at `create()`; claimed members pledge coins toward the one they
want; **pledging IS the vote**; the market resolves the moment the leading egg
is fully funded. The winning candidate seed becomes the group's seed.

New: `src/market/rules.ts` (pure, shared by app and worker), `src/market/index.ts`
(app only, pulls three.js via `paletteFor`), `src/ui/Market.tsx`,
`test/market/rules.test.ts`, `test/worker/market.test.ts`.

Locked decisions, decided by the product owner, **do not re-litigate**:

1. Purse is 100 coins per claimed member, granted once at claim. No other
   source of money exists in this unit.
2. Prices: plain egg **flat 75** at every headcount; middle `55 + 50n`; fine
   `70 + 55n`, where n is claimed members. The plain egg is flat on purpose,
   see section 5.
3. **The eggs keep their hatch speeds** (0.75, 1, 1.5). An earlier plan to
   remove them was WRONG and was reverted before any code was deleted. See
   section 6.
4. Existing groups are GRANDFATHERED, not reset: a group with a seed already
   has its creature and never sees a market.
5. Only a claimed member (`@` prefixed actorId) may pledge. Anonymous visitors
   watch.
6. A pledge SETS an amount, it does not add one. Zero is how you take coins
   back. This is why there is a unique index on `pledges(actorId, egg)`.

## 4. Known defects, in priority order

All thirteen survived three-way adversarial refutation. Nothing here is a guess.

**Blocking a deploy:**

1. **Refusals still do not reach two of the three screens.** The routing landed
   in `ActionBar`'s `.settle` line only. On a phone the claim panel is a modal
   `<dialog>` that covers it, and NO component on the market screen subscribes
   to the sentence store at all, so every refusal a group meets while choosing
   an egg is rendered nowhere. The fix that was made is right; it is one place
   short of two.
2. **`claim()` reads its bounds before an `await` and writes after it.** Two
   claim messages arriving in one batch both pass the per-device guard and the
   `MAX_CLAIMED` bound, so one person can still mint two purses on one device
   and a group can exceed its own limit. This is a genuine race, distinct from
   the two-tabs limit in item 6 which cannot be closed at all.
3. **The purchase is still recorded nowhere.** The agent briefed to do it
   correctly refused: the only channel to the chronicle is
   `deriveCreature(genome, actions, ...)`, and a memory saying who paid what is
   a fact the server knows and a client cannot recompute, so writing it would
   weaken the pure-function doctrine. It needs `express.ts`, `types.ts` and
   `useGroup.ts` together, as its own unit. **Do not solve it by weakening
   purity.**

**Tests that cannot fail** (each verified by deleting the rule it names):

4. `test/worker/market.test.ts:636`, the refund test, asserts only
   `bought.spent`, which `resolutionOf` computes BEFORE `resolve()` touches a

5. `test/ui/code-entry.test.ts:62` is answered by an identical line in a
   different component, so deleting the guard it names leaves it green.
6. Nothing at any level covers the refusal routing or the cancelled-pointer fix,
   so both changes can be reverted with no test going red.

**Real but not blocking:**

7. `connection.ts` treats ANY error arriving in the code window as the answer to

## 5. Traps this repo has already paid for

Every one of these caused a real defect in this codebase. They are the checklist.

- **A negative test goes green the moment ANY rule refuses.** A fresh group is
  an EGG and about twenty variants are gated to `minStage: 1`, and a group at
  the market refuses every ordinary action. So a refusal test written with
  `feed.*` is answered by a gate it does not name. Two tests passed that way for
  a week while the rule they named had never been wired up at all. Build every
  fixture so every OTHER gate would pass, and put a positive control beside each
  negative test.
- **A gate can be green while covering almost nothing.** A genome pin test with
  24 seeds stayed green against a one-in-twenty defect. Rebuilt at 400 seeds
  (20 buckets of 20) it fired immediately. Sample size is part of the gate.
- **The catalogue is production state.** The server calls `rollGenome(seed)` on
  every read; it does not store genomes. `HABIT_SHAPES` in `alleles.ts` is
  summed off `ACTION_VARIANTS`, so adding one ordinary action variant re-deals
  the alleles of creatures that already exist. Measured: 23 in 500.
  `test/dna/genome-pin.test.ts` is what notices. **If it goes red, do not update
  the hashes.** The proper fix is freezing the genome at creation, which is a
  migration over every live group and wants its own unit.
- **`CREATE TABLE IF NOT EXISTS` does nothing to a table that exists.** Adding a
  column to the DDL adds it for new groups only and 500s every existing one.
  That has happened here. Every ALTER lives in its OWN try block, because
  sharing one means a group that already has the first column never gets the
  second. `forgetGrowthColumn()` is the sabotage hook the migration tests use;
  anything you add must drop there too.
- **A parallel fleet's defect lands on the seam.** An agent that hits a shared
  problem solves it inside the file it owns and never tells the other side. That
  shipped a half-hour "rouse" in the worker that the app knew nothing about, so
  waking a sleeping creature worked on the server and did nothing on screen,
  with 265 tests green. If two sides must agree on a number, put it in ONE
  shared function with a REQUIRED parameter so the compiler forces it.
- **A built thing may have no caller.** Fully unit-tested code that nothing on a
  player's path ever calls has shipped here twice.

## 6. The hatch speed correction, so nobody redoes it

A research audit claimed the pace dial makes the eggs' hatch speeds worthless,
because `growthNow` multiplies by pace (0.25 to 6) and hatch speed only spans
0.75 to 1.5.

**That claim does not hold and the eggs keep their hatch speeds.** Pace
multiplies all three eggs equally, so the fine egg is exactly twice as fast as
the plain one at every pace setting. The market's copy is relative ("the
shortest wait of the three", `src/market/index.ts`) and never states an hour, so
it stays true. `index.ts` already documents why the hours are never shown.

A workflow that was deleting the machinery was stopped before it wrote anything.
Do not remove `hatchSpeed`, `hatchAdjusted`, `EGG_ENDS`, `HATCH_SPEEDS` or
`waitPhrase`.

## 7. Deploying, which is more dangerous than it looks

The site repo is `D:\Programs\tevded-site`. Read the constraints in
`docs/RESUME.md` as well.

- **A deploy publishes FILESYSTEM STATE, not git.** `public/` holds fifteen app
  folders. Anything another session has staged there goes live with your deploy,
  committed or not.
- `npm run stage` (in this repo) copies the build into the site. `npm run deploy`
  (in the site repo) publishes.
- **`wrangler versions upload` does NOT publish static assets.** It uploaded the
  worker while leaving the live page pointing at a deleted bundle. Use it to
  prove the worker builds, then `npm run deploy` for real.
- **Every path returns 200**, because a missing file under a `_headers` rule
  serves the site fallback wearing the correct Content-Type. Judge by `<title>`
  and by BYTE SIZE against your local `dist/`, never by status code.
- A deploy can fail once with a Cloudflare API error and succeed on retry with
  nothing changed. Retry before believing it.
- The edge can serve a stale HTML for a minute or two after a real deploy. Use a
  cache-busting query and re-check rather than assuming failure.

## 10. Standing rules that govern all of this

- No em-dashes or en-dashes anywhere. No emojis on any product surface.
- No mechanics in player-facing copy: no axis names, no pressure numbers, no
  hour counts. Coins ARE shown, because money somebody is spending is not a
  hidden mechanic. The reason is that a readable mechanic gets optimised, and an
  optimised creature is the same creature every group gets.
- Never introduce visual or UX changes that were not asked for. Honed surfaces
  are protected. List every visual delta.
- The creature is a PURE FUNCTION of (seed, ordered action log). `src/dna` is
  gated by `test/dna/purity.test.ts`: no `Math.random`, no clock reads, no
  transcendentals, no `**`, no `for...in`, no `Object.keys/entries/values` where
  order matters. Wall-clock time enters as a PARAMETER.
- One commit per unit, with the gates run first. Effort is S/M/L/XL, never day
  estimates.
